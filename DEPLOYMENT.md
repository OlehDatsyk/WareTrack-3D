# Deploying WareTrack 3D

WareTrack 3D is a standard Next.js Node server backed by PostgreSQL. It needs:

1. A PostgreSQL 15+ database.
2. Migrations applied before the new version starts: `npx prisma migrate deploy`.
3. *(Optional)* Demo data on first deploy: `npm run db:seed-if-empty`. It is safe to run on every deploy because it only seeds when the database has no users.

The health check endpoint is **`GET /api/health`**. It returns `200 {"status":"ok","database":"up"}`, or `503` if the database is unreachable.

---

## Option A — Render Blueprint (recommended)

`render.yaml` defines a **free** web service (`waretrack-3d`, region Frankfurt). It **shares an existing Render Postgres instance** (`remixfox-db`), because a Render workspace can only hold one free Postgres. All WareTrack tables live in their own schema (`DATABASE_SCHEMA=waretrack`), so the other application's data in `public` is never touched. This includes the demo reset, which only truncates tables in WareTrack's own schema. The database is only referenced through `fromDatabase`, so the Blueprint never changes its settings.

1. Push the repository to GitHub. Make sure `.env` is **not** committed (it is git-ignored).
2. In Render, choose **New → Blueprint** and select the repository.
3. Click **Deploy Blueprint**. Render injects `DATABASE_URL` from the referenced database, builds with `npm ci && npm run build`, and starts with `npx prisma migrate deploy && npm run db:seed-if-empty && npm start`. Migrations and the first-run seed are idempotent and stay inside the `waretrack` schema. Render then monitors `/api/health`.
4. Free-tier notes:
   - The web service sleeps after about 15 idle minutes, and the first request wakes it in about a minute.
   - A free Render database expires 30 days after it was created, and WareTrack's data goes with it.
   - To move WareTrack onto its own database, add a `databases:` entry (or use an external Postgres) and point `DATABASE_URL` at it. You can then remove `DATABASE_SCHEMA` or keep it.
5. Open the service's **Environment** tab and copy the generated `SEED_DEMO_PASSWORD`. Use it with `manager@waretrack.demo` (or any demo account) to sign in.
6. **Recommended for any shared deployment:** sign in as `admin@waretrack.demo`, create real users under **Settings → Users**, change the demo passwords or deactivate the demo users, and set `NEXT_PUBLIC_DEMO_MODE=false`.

### Environment variables

| Key | Required | Notes |
| --- | --- | --- |
| `DATABASE_URL` | yes | Injected from the referenced Render database |
| `DATABASE_SCHEMA` | no | Postgres schema for all WareTrack tables (`waretrack` on Render; unset = `public`) |
| `SEED_DEMO_PASSWORD` | for seeding | 10+ characters, generated by the Blueprint |
| `SEED_DEMO_DATA` | no | `false` to start with an empty database |
| `SESSION_TTL_HOURS` | no | Default 12 |
| `NEXT_PUBLIC_DEMO_MODE` | no | `false` hides the demo-account helper (build-time variable, so redeploy after changing it) |
| `NODE_VERSION` | no | `22` |

### Manual seed / reset on Render
From the service **Shell**:
```bash
npm run db:seed            # WARNING: wipes all data and reseeds the demo
npm run db:seed-if-empty   # only seeds an empty database
```

## Option B — Docker

```bash
docker build -t waretrack-3d .
docker run -p 3000:3000 \
  -e DATABASE_URL="postgresql://user:pass@host:5432/waretrack" \
  -e SEED_DEMO_PASSWORD="choose-a-strong-password" \
  waretrack-3d
```

The container runs `prisma migrate deploy`, then `db:seed-if-empty`, then `next start`. It includes a `HEALTHCHECK` against `/api/health` and runs as a non-root user.

---

## Option C — Any Node host

```bash
npm ci
npm run build
npx prisma migrate deploy
npm run db:seed-if-empty     # optional
npm start                    # PORT defaults to 3000
```

## Production notes

- **Sessions** are stored in the `Session` table, and only a SHA-256 hash of each token is kept. Cookies are `httpOnly`, `SameSite=Lax`, and `Secure` in production. Serve over HTTPS (Render does this by default).
- **Rate limiting** of sign-in and registration is in-memory per instance. When you scale to several instances, move it to a shared store such as Redis.
- **Simulation:** each warehouse's simulation advances only while a signed-in client is polling it. No background worker is needed. Turn it off per warehouse under **Settings → Warehouse** or with the top-bar pill.
- **Security headers** (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`) are set in `src/proxy.ts`.
- **Error handling:** API errors return `{ error: { code, message } }` without stack traces. Unexpected errors are logged server-side with an `[api]` prefix.
- **Backups:** enable Render Postgres backups, or your provider's equivalent.
- **Real GPS / telematics:** the route map is schematic and simulated. To integrate a real tracking provider, update `Shipment.routeProgress` / `destMapX/Y` (or add a position table) from a webhook route, and keep the UI label accurate.
